# callback-data

Flat, compile-time-checked `callback_data` (de)serialization for Telegram
bots — an aiogram-`CallbackData`-flavored crate for Rust. Framework-agnostic
by default, with optional [`telers`](https://crates.io/crates/telers)
integration behind a feature flag.

```rust
use callback_data::{callback_data, CallbackDataTrait};

#[derive(Debug, Clone, PartialEq, callback_data::FlatField)]
enum Action {
    Ban,
    Kick { reason_code: u32 },
}

#[callback_data(prefix = "adm")]
struct AdminAction {
    #[callback_data(owner)]
    user_id: i64,
    action: Action,
    target: Option<i64>,
}

let data = AdminAction { user_id: 1, action: Action::Ban, target: None };
let packed = data.pack()?;                 // "adm:1:0::~:"
let parsed = AdminAction::unpack(&packed)?; // back to `AdminAction`
```

## Why not just `serde_json`?

Because `serde_json` (or any self-describing format) doesn't know your
schema — it has to guess types from the data itself, which is exactly what
breaks on things like untagged enums or a string that happens to look like
a number. This crate goes the other way: every field's type is known at
compile time via the `FlatField` trait, so packing/unpacking never guesses,
never panics, and rejects unsupported types (`Vec`, `HashMap`,
`serde_json::Value`, ...) as a **compile error**, not a runtime surprise.

## What's supported

**Primitives** (packed as plain text, no quotes): `u8..u128`, `i8..i128`,
`usize`/`isize`, `f32`/`f64`, `bool` (`t`/`f`), `String`.

**Nested types** — any type deriving `FlatField` flattens straight into the
parent's token list:

```rust
#[derive(callback_data::FlatField)]
struct Extended { value: i32 }

#[callback_data(prefix = "x")]
struct MyData {
    id: u64,
    extended: Extended, // flattens: "x:<id>:<value>"
}
```

**Enums** — encoded as a variant-index token followed by that variant's
fields, padded to the widest variant so the total token count is fixed at
compile time:

```rust
#[derive(callback_data::FlatField)]
enum Action {
    Ban,                      // index 0, no fields
    Kick { reason_code: u32 }, // index 1, 1 field
}
```

Only unit variants and named-field variants are supported (no tuple
variants) — this keeps field names available and keeps the encoding
unambiguous.

**`Option<T>`** — treated as a 2-variant enum: a 1-token tag (`~` = `None`,
`s` = `Some`) followed by `T`'s tokens (present but ignored when `None`, to
keep the token count fixed).

**Not supported, on purpose**: `Vec`, `HashMap`, any variable-length
collection, `serde_json::Value`, `#[serde(untagged)]` enums — anything whose
shape isn't knowable purely from the type at compile time.

## Safety guarantees

- **No raw SQL-style string surprises**: separators (`:`) and the reserved
  `Option` markers are validated on every `pack()` call — a string field
  containing `:` fails to pack instead of silently corrupting the format.
- **Round-trip self-check**: `pack()` immediately tries to `unpack()` what
  it just produced, and fails loudly if they don't match, instead of
  handing you a button that will silently fail later.
- **Never panics on `unpack()`**: a stale button from before you renamed,
  added, or removed a field just returns `Err` — your filter skips it, the
  bot keeps running.

## Ownership checks — deliberately not built in

There's no `filter_from_user`-style flag baked into the macro. Instead,
mark the relevant field (its type must be `i64`, matching `call.from.id`
in `telers`):

```rust
#[callback_data(prefix = "adm")]
struct AdminAction {
    #[callback_data(owner)]
    user_id: i64,
    action: Action,
}
```

which overrides `CallbackDataTrait::owner_id(&self) -> Option<i64>` for
this type (it's `None` by default for types with no marked field):

```rust
if data.owner_id() != Some(call.from.id) {
    // your response, your text, your i18n, your `show_alert`/`cache_time` —
    // this crate has no opinion on any of it.
}
```

This crate only tells you *whether* a callback belongs to someone. What
happens on a mismatch (localized text, alert flag, logging, silence) is
entirely up to your own filter/middleware/handler.

### A single global ownership middleware

Because `owner_id()` always returns a plain `Option<i64>` — not some
type-erased trait object — a middleware that doesn't know (and shouldn't
need to know) which concrete callback-data type matched can still check
ownership. With the `telers` feature, `CallbackDataFilter<T>` writes
`owner_id()` into the request context under the fixed key
[`OWNER_ID_CONTEXT_KEY`] on *every* match, unconditionally — even `None`
for types without an owner field — so it's never left over from a
previous filter in the chain:

```rust
// registered once, globally, with no generic parameter over T:
if let Some(Some(owner)) = request.context.get::<Option<i64>>(callback_data::OWNER_ID_CONTEXT_KEY) {
    if *owner != call.from.id {
        // your response
    }
}
```

## Feature flags

### `telers` (off by default)

Adds:

- `CallbackDataButtonExt::button(text)` — build an `InlineKeyboardButton`
  directly from a callback-data value.
- `CallbackDataFilter<T>`, implementing `telers::Filter<Client>` generically
  over the HTTP client (not hardcoded to `Reqwest`) — unpacks a matching
  update's `callback_data` into `T` and inserts it into the request context
  under `"callback_data"`.

```rust
use callback_data::{as_filter, CallbackDataButtonExt};

router.callback_query.register(handler, as_filter::<AdminAction>());

let button = data.button("Ban")?;
```

Without this feature, the crate has zero dependency on `telers` and can be
used with any framework (or none).

### `merge` (off by default)

A separate, `serde`-based mechanism for merging fields between two
*different* callback-data types by field name — unrelated to `pack`/
`unpack`, which never touch `serde`. This is a deliberately unchecked,
runtime, stringly-keyed operation (a fully type-checked generic merge
between arbitrary types would need HList-style reflection, which isn't
worth the complexity here):

```rust
use callback_data::{fields, MergeTo};

let data2: Data2 = data1.merge_to(fields! { value: 1 })?;
```

Requires `#[derive(Serialize, Deserialize)]` in addition to your usual
`FlatField`/`callback_data` derives.

## What this crate does *not* do

- No filtering by field value (`F.foo == "demo"`-style, as in aiogram) —
  unpack the callback data and check the field yourself in the next filter.
- No generic merge across arbitrary types without `serde`.
- No support for types requiring self-describing (de)serialization
  (`Vec`, `HashMap`, `serde_json::Value`, untagged enums).
